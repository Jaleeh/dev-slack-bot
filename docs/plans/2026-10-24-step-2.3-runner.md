# Step 2.3: Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `make eval` fetches django-oscar at `4.2.1` once, checks every answer-key file exists, scores a retriever on recall@5, recall@10 and MRR, prints a summary and saves a results file.

**Architecture:** `evals/sample_repo.py` owns the cached shallow clone. `evals/retriever.py` holds the `Retriever` protocol and the `AnswerKeyRetriever` stand-in. `evals/runner.py` loads the question set, fetches, checks files, times each `retrieve` call, scores with 2.1's maths, and writes JSON. Scoring is pure; fetching, timing and writing are the shell.

**Tech Stack:** Python 3.14, Pydantic v2, the `git` CLI via `subprocess`, pytest, Ruff, mypy (strict). No new dependencies.

**Spec:** [`docs/specs/2026-10-24-step-2-evals.md`](../specs/2026-10-24-step-2-evals.md), section "2.3 Runner"

## Global Constraints

- Branch `step-2.3-runner`. One PR, code only.
- Sample repo: `https://github.com/django-oscar/django-oscar.git`, tag `4.2.1`, shallow clone.
- Clone cache: `backend/evals/.cache/` (git-ignored). Results: `backend/evals/results/<UTC timestamp>.json` (git-ignored).
- `make eval` runs on the host with `uv run`. No Ollama, no database.
- Results fields, exactly: `started_at`, `git_commit`, `dataset_version`, `repo`, `ref`, `retriever`, `metrics` (mean recall@5, recall@10, MRR), `questions` (per question: id, ranked results, recall@5, recall@10, reciprocal rank, `seconds`, `tokens`).
- `tokens` is a typed optional; `None` for the stand-in.
- The integration test uses a tiny local git repo made inside the test, never Oscar or the network.
- Every metric must be shown to move: one run scoring 1.0 and one scoring 0.0.
- **Commit only when the user says so.** The commit steps below are there for when they do.

## Builder's calls

- **`repo` → URL lookup lives in `sample_repo.py`** as `REPO_URLS = {"django-oscar": "https://github.com/django-oscar/django-oscar.git"}`. `questions.yaml` stays as 2.2 left it. The runner config takes the mapping so the test can point it at a local repo.
- **Cache folder per repo and ref:** `.cache/<repo>@<ref>`. Changing the ref fetches a fresh clone instead of silently reusing the old one.
- **Clone into a temp folder, then rename.** A fetch that dies halfway leaves nothing behind that a later run would mistake for a good clone.
- **`git_commit` gets a `-dirty` suffix** when this repo has uncommitted changes. A result from uncommitted code shouldn't look reproducible.
- **`tokens` stays `None` in this slice.** The spec fixes `retrieve` to return `list[str]`, so step 3 decides how a retriever reports tokens.
- **Results file name:** `datetime.now(UTC).strftime("%Y%m%dT%H%M%SZ") + ".json"`.
- **Summary table:** plain aligned text, no new library. Rows: retriever, questions, recall@5, recall@10, MRR (3 decimals), results path.
- **`make eval` takes no options yet.** Choosing a retriever comes with step 3, when there is a second one.
- **Carried from 2.2:** the runner catches `InvalidQuestionSet` and `yaml.YAMLError` and stops with a clear message. PyYAML keeping the last duplicate key stays deferred.

## Review Focus

1. **A fetch that fails halfway** (network drop, bad ref). No half-clone is left in the cache; the next run fetches cleanly. Tested in Task 1.
2. **`git` not installed.** Stops with a clear `SampleRepoError`, not a raw `FileNotFoundError`. Tested in Task 1.
3. **The ref changes after a cached run.** The new ref gets its own clone. Tested in Task 1.
4. **A file in the answer key that isn't in the clone.** The run stops and lists every missing path, before any scoring. Tested in Task 2.
5. **A broken `questions.yaml`.** `make eval` prints the problems and exits 1, with no traceback. Tested in Task 3.

- Produces:

    - `RunResult`: `started_at: AwareDatetime`, `git_commit`, `dataset_version: int`, `repo`, `ref`, `retriever: str`, `metrics: Metrics`, `questions: tuple[QuestionResult, ...]`
