# Step 2.4: PII Set Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A set of about 25 snippets with about 50 planted fake personal values and their look-alikes, plus a format check that loads it into frozen models and rejects bad entries by name.

**Architecture:** `evals/pii_set.py` holds frozen Pydantic models and one loader, the same shape as `evals/question_set.py`. The YAML loading and error naming that both files need moves into `evals/dataset_file.py` first. The data lives in `evals/datasets/pii.yaml`. Scoring and runner wiring are 2.5, not this slice.

**Tech Stack:** Python 3.14, Pydantic v2, PyYAML, pytest, Ruff, mypy (strict). No new dependencies (`ipaddress` is stdlib).

**Spec:** [`docs/specs/2026-10-24-step-2-evals.md`](../specs/2026-10-24-step-2-evals.md), section "2.4 PII set"

## Global Constraints

- Branch `step-2.4-pii-set`. One PR: the data and its format check (the same split as 2.2).
- About 25 snippets, about 50 planted values. About half `question`, half `code`.
- Questions sound like support staff. Code looks like real settings files, fixtures, logs and comments.
- Types: `PERSON`, `EMAIL`, `PHONE`, `UK_NINO`, `CARD`, `IP`, `SECRET`, `ADDRESS`, `DATE_OF_BIRTH`. Fake values come only from the spec's source table.
- Look-alikes: variable names (`user_email`, `phone_number`), bare domains, version strings (`4.2.1`), order numbers in Oscar's own format, dates that aren't birthdays, hex commit hashes.
- Format check (spec): every planted value and every look-alike appears exactly in its `text`; ids are unique; `type` is from the list; no word of 3 or more letters from a `PERSON` or `ADDRESS` value appears elsewhere in the `text`.
- No real personal data, ever. Every value must be fake.
- **Commit only when the user says so.**

## Builder's calls

- **Shared loader first.** `load_question_set` already turns Pydantic errors into messages that name the entry by id. `load_pii_set` needs the same, so that code moves to `evals/dataset_file.py` instead of being copied. `InvalidQuestionSet` becomes `InvalidDataset`, and the runner's import changes with it.
- **Word matching is case-sensitive and by substring**, the same as 2.5's scoring. Case-sensitive is required: the spec's own example has `John Doe` next to `john.doe@example.com`, which a case-blind rule would reject. Substring (not whole word) matters because 2.5 would count `Doe` inside `Doesn't` as a leak.
- **Rules beyond the spec,** each guarding something the spec cares about:
  - **A look-alike must appear outside the planted values.** If `example.com` only appears inside `jane.roe@example.com`, a perfect redactor removes it and gets a wrong flag, so `AnswerKeyRedactor` could not score 0 as 2.5 requires.
  - **A value can't be planted twice, and a look-alike can't be listed twice, in one snippet.** Either would be counted twice.
  - **Planted values can't overlap in the text.** A name sharing a word with an address can't be removed cleanly, so `AnswerKeyRedactor` couldn't score 1.
  - **A snippet must plant something or list a look-alike.** An empty one measures nothing.
  - **Fake-source checks** for the types where it's cheap: `EMAIL` is one address at `example.com`/`.org`/`.net`, `PHONE` in the two Ofcom drama ranges, `UK_NINO` a full number with the `QQ` prefix, `CARD` one of four published test cards (each passes Luhn), `IP` in RFC 5737. These stop real data slipping in and enforce the "too fake" anti-goal. Luhn alone was dropped: every real card passes it. `PERSON`, `ADDRESS`, `DATE_OF_BIRTH` and `SECRET` are left to maintainer review.
- **`PiiType` is a `StrEnum`**, so 2.5 can group catch rates by it.
- **`name_words(value)` is public**, because 2.5 must use the same definition of "word of 3 or more letters" when it scores a partial name leak.

## Review Focus

1. **A look-alike that only appears inside a planted value** (`example.com` inside an email). Must fail. Tested in Task 2.
2. **A name word inside a longer word** (`Doe` in `Doecraft`). Must fail, since 2.5 matches by substring. Tested in Task 2.
3. **A card that isn't a published test card** (`4111 1111 1111 1112`, or a Luhn-valid `4000 0000 0000 0002`). Must fail. Tested in Task 2.
4. **A real-looking value outside the reserved ranges** (`x@gmail.com`, `8.8.8.8`). Must fail. Tested in Task 2.
5. **GitHub push protection blocking a fake `SECRET`.** Use vendor-published example keys (AWS's `AKIAIOSFODNN7EXAMPLE` is allow-listed) and obviously fake tokens. If a push is blocked, swap the value; never bypass the block. Checked when the PR is pushed.

- [ ] **Step 3: Implement `evals/pii_set.py`** with the interfaces above.

- All models: `ConfigDict(frozen=True, extra="forbid")`.
- `PlantedValue` gets one `model_validator(mode="after")` with a `match` on `type` for the five fake-source checks. Every other type passes.
  - `EMAIL`: fullmatches `[^@\s]+@example\.(com|org|net)`.
  - `PHONE`: drop spaces, turn a leading `+44` into `0`, then the digits match `07700900\d{3}` or `02079460\d{3}`.
  - `UK_NINO`: fullmatches `QQ ?\d{2} ?\d{2} ?\d{2} ?[A-D]`.
  - `CARD`: with spaces dropped, one of `4111111111111111`, `4242424242424242`, `5555555555554444`, `378282246310005`.
  - `IP`: `ipaddress.ip_address` parses it and it's in `192.0.2.0/24`, `198.51.100.0/24` or `203.0.113.0/24`. A parse error gives the same message.
- `Snippet` gets one `model_validator(mode="after")` for the text rules. Build the "text outside planted values" by replacing each planted value with `"\x00"` (a character no value contains, so the gaps can't join into new words). Then:
  - each planted value is in `text`;
  - no planted value or look-alike repeats;
  - no planted value vanishes once the others are masked (overlap);
  - each look-alike is in the masked text;
  - for `PERSON` and `ADDRESS`, each of `name_words(value)` is not in the masked text (so a name inside another planted value, like `John.Doe@example.com`, is allowed);
  - planted or look-alikes is non-empty.
  Collect every problem and raise one `ValueError` listing them, so a bad snippet shows all its problems at once.
- `PiiSet` gets the unique-id validator, the same as `QuestionSet`.
- `load_pii_set` is `load_dataset(path, PiiSet)`.
- Keep each validator under 50 lines; extract the fake-source checks into small `_check_<type>` functions if the `match` grows.
