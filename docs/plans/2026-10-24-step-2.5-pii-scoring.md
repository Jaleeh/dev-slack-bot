# Step 2.5: PII Scoring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Score any redactor against the fake PII set (catch rate overall and per type, wrong-flag rate), ship two stand-ins, and add the PII scores to `make eval` and its results file.

**Architecture:** `evals/redactor.py` holds the `Redactor` seam and its two stand-ins, the same shape as `evals/retriever.py`. `evals/pii_metrics.py` is pure: it takes a snippet and the redacted text and returns frozen result models. The runner loads the PII set next to the question set, runs the redactor over every snippet, and nests the PII results under `pii` in the same results file.

**Tech Stack:** Python 3.14, Pydantic v2, pytest, Ruff, mypy (strict). No new dependencies. Presidio is step 4.

**Spec:** [`docs/specs/2026-10-24-step-2-evals.md`](../specs/2026-10-24-step-2-evals.md), section "2.5 PII scoring"

## Global Constraints

- Branch `step-2.5-pii-scoring`. One PR, code only.
- Interface, verbatim from the spec: `class Redactor(Protocol): name: str; def redact(self, text: str) -> str: ...`
- **Caught:** the exact value no longer appears in the output. For `PERSON` and `ADDRESS`, every word of 3 or more letters must also be gone. Other types are checked on the exact value only.
- **Matching** is a plain, case-sensitive substring search on the output.
- **Wrongly flagged:** a look-alike that no longer appears exactly in the output.
- **Catch rate** = caught / planted, overall and per type. **Wrong-flag rate** = wrongly flagged / look-alikes, overall.
- Stand-ins: `NoRedactor` (text unchanged, catch rate 0) and `AnswerKeyRedactor` (removes exactly the planted values, catch rate 1, wrong-flag rate 0).
- `make eval` reports PII scores for `NoRedactor`, labelled as a stand-in.
- No model, no network, no database.
- **Commit only when the user says so.**

## Builder's calls

- **Results nest under `pii`.** The PII set has its own `version`, so `RunResult` gains `pii: PiiResult` holding `dataset_version`, `redactor`, `metrics` and `snippets`, instead of flat fields that would clash with the retrieval ones.
- **`evaluate` takes a `Contenders` pair** instead of a third argument: `Contenders(build_retriever, build_redactor)`. The existing runner tests change their calls to match.
- **Both datasets load before the clone is fetched**, so a broken `pii.yaml` stops the run before any network work.
- **An empty denominator gives `None`, not a crash.** A valid PII set may have no look-alikes (2.4 allows snippets with none), so a rate with nothing to measure is `None` and the summary prints `n/a`.
- **Per-type rates cover only the types in the set.** A missing type gets no key, not 0.
- **`AnswerKeyRedactor` replaces each value with `<TYPE>`** (e.g. `<PERSON>`), longest first, which matches Presidio's default output. The 2.4 format check already guarantees the look-alikes survive this.
- **`NoRedactor.name` is `"none (stand-in)"`**, so both the summary and the results file carry the stand-in label.
- **Summary shows overall rates only.** Per-type rates are in the results file.

## Review Focus

1. **A partial name leak** (`John <PERSON>` left behind). Must be a miss. Tested in Task 1.
2. **A name word left inside a longer word in the output** (`Doe` inside `Doesn't`). Counts as a miss, the same substring rule as the 2.4 format check. Tested in Task 1.
3. **A value that appears twice in the text, and only one copy is removed.** Must be a miss. Tested in Task 1.
4. **A set with no look-alikes.** Wrong-flag rate is `None`, the summary prints `n/a`, and nothing crashes. Tested in Tasks 1 and 3.
5. **A broken `pii.yaml`.** `make eval` stops with the snippet id and exit code 1, no traceback. Tested in Task 3.

- Produces:
  - `class Redactor(Protocol)`: `name: str`; `def redact(self, text: str) -> str`
  - `class NoRedactor`: `name = "none (stand-in)"`, returns the text unchanged
  - `class AnswerKeyRedactor`: `name = "answer-key"`, `__init__(self, pii_set: PiiSet)`, replaces each planted value in a known snippet text with `<TYPE>`, longest value first. An unknown text raises `KeyError`, the same as `AnswerKeyRetriever`.

- [ ] **Step 1: Write the failing tests.** Both run against the real `pii.yaml`, which proves the stand-ins and the 2.4 data agree.

```python
def test_no_redactor_scores_zero_on_the_pii_set() -> None:
    metrics = score_with(NoRedactor())
    assert metrics.catch_rate == 0.0
    assert metrics.wrong_flag_rate == 0.0


def test_answer_key_redactor_scores_full_marks_on_the_pii_set() -> None:
    metrics = score_with(AnswerKeyRedactor(load_pii_set(PII_PATH)))
    assert metrics.catch_rate == 1.0
    assert set(metrics.catch_rate_by_type.values()) == {1.0}
    assert metrics.wrong_flag_rate == 0.0
```

`score_with(redactor)` is a test helper: load the set, `score_snippet` each snippet on `redactor.redact(snippet.text)`, then `pii_metrics`.
