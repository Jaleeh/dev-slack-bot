# Step 3.1: Search Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four language-agnostic tools — `list_files`, `grep`, `read_file`, `outline` — that let the step 3.2 agent search a repository folder safely.

**Architecture:** A new `app/retrieval/direct/` package. `scope.py` decides which paths are inside the repository and not ignored (`.gitignore` plus a noise list). `outline.py` turns a file into symbols with tree-sitter. `search.py` holds `DirectSearch`, whose four methods are the tools and return plain text for the model. Every failure raises a `SearchError` subclass whose message the model can act on. Step 3.2 turns those into tool replies. Decisions (path checks, enclosing-symbol lookup, output formatting) are pure functions. File reads stay in thin methods.

**Tech Stack:** Python 3.14, `tree-sitter-language-pack` 1.22, `pathspec` 1.1, pytest, Ruff, mypy (strict).

**Spec:** [`docs/specs/2026-10-27-step-3-direct-retrieval.md`](../specs/2026-10-27-step-3-direct-retrieval.md), section "3.1 Search tools"

## Findings from probing the libraries (2026-10-27)

- **`tree-sitter-language-pack` 1.x downloads grammars on first use.** The grammars are checksum-checked shared libraries, cached in the user cache folder. They are not bundled with the package. The spec's "ships ready-built support" is wrong on this point. Grammars are ready-built but fetched per language. That's fine for step 3, which runs on the host. Step 5's Docker image must prefetch them, and `tech-stack.md` says so (Task 6).
- `process(source, ProcessConfig(language=..., structure=True)).structure` already returns the outline: `kind`, `name`, `signature`, `span` (0-based lines) and `children`. No tree-sitter queries are needed.
- `detect_language_from_path` returns `None` for an unknown extension. An unknown language name raises `DownloadError`. Broken code still yields partial structure.
- **`grep-ast` is not adopted.** It works with language pack 1.x. But it prints every enclosing scope's lines, so its output size is hard to cap, and the spike's empty answer may be a context overflow. Labelling each hit with its enclosing symbol name (from `outline`) gives the same help in one bounded line, with no extra dependency.
- `pathspec.GitIgnoreSpec.from_lines` handles `.gitignore` rules, including `!` negation. Both packages ship type hints (`py.typed`).

## Global Constraints

- Branch `step-3.1-search-tools`, stacked on `step-3-spec` (`gh stack`).
- `app/retrieval/direct/` imports nothing from `evals/` or other `app/` features.
- All paths given to and returned by the tools are relative to the repository root, using forward slashes.
- Every tool skips `.git/`, the repository's `.gitignore`, and the skip patterns. `DEFAULT_SKIP` = `("**/migrations/", "node_modules/", "vendor/", "*.lock", "package-lock.json", "*.min.js", "*.min.css")`.
- Limits: `MAX_READ_LINES = 200`, `MAX_GREP_HITS = 40`, `GREP_CONTEXT_LINES = 1`, `BINARY_SNIFF_BYTES = 8192` (a file with a NUL byte in its first 8 KB is binary).
- `grep` is case-insensitive. Files are read as UTF-8 with `errors="replace"`.
- The tool methods' parameters mirror what the model sends, so `read_file(path, start_line, end_line)` keeps three arguments. That's the model's contract, not a design choice.
- Expected values in tests are hard-coded. One behaviour per test.
- **Commit only when the user says so.** The commit steps below are there for when they do.

## Review Focus

1. **A symlinked file inside the repo that points outside it** (`docs/link.txt → /tmp/outside/secret.txt`). `grep` must never print its content, and `read_file` must refuse it. Tested in Tasks 2 and 5.
2. **A model-sent path like `/etc/passwd`, `../x` or `src/../../x`.** Refused with `PathOutsideRepo`, never read. Tested in Task 2.
3. **A huge or invalid regex** (`(`, `[a-`). The model gets `BadPattern` with the reason, and nothing crashes. Tested in Task 5.
4. **`read_file` past the end of a file** (`start_line=900` on a 450-line file), or `end_line < start_line`. A `BadLineRange` that names the file's length. Tested in Task 3.
5. **A file in a language with no grammar, or a grammar that can't be downloaded offline.** `outline` raises `CannotOutline` advising `read_file`. `grep` still works and just omits the symbol label. Tested in Tasks 4 and 5.

### Task 2: Scope — paths inside the repo, ignore rules, text files

**Files:**
- Create: `backend/app/retrieval/__init__.py`, `backend/app/retrieval/direct/__init__.py` (empty)

- Create: `backend/tests/unit/retrieval/__init__.py`, `backend/tests/unit/retrieval/conftest.py`, `backend/tests/unit/retrieval/test_scope.py`

**Interfaces:**
- Produces (`errors.py`): `SearchError(Exception)`. Subclasses, each storing its fields as attributes, with a message the model can act on:
  - `PathOutsideRepo(path: str)`: "… is outside the repository"
  - `PathNotFound(path: str)`: "no such file or folder: …"
  - `NotAFolder(path: str)`
  - `BadPattern(pattern: str, reason: str)`
  - `BadLineRange(path: str, start_line: int, end_line: int, line_count: int)`
  - `CannotOutline(path: str, reason: str)`: the message ends "use read_file instead"
- Produces (`scope.py`):
  - `DEFAULT_SKIP: tuple[str, ...]` (Global Constraints)
  - `@dataclass(frozen=True) class SearchScope: root: Path; ignore: pathspec.GitIgnoreSpec`
  - `open_scope(root: Path, skip: Sequence[str] = DEFAULT_SKIP) -> SearchScope`: the resolved root, plus a spec built from `.git/`, `skip` and the lines of `root/.gitignore` if it exists
  - `resolve(scope: SearchScope, path: str) -> Path`: an absolute resolved path, inside the root and existing. It raises `PathOutsideRepo` before `PathNotFound`. An ignored path raises `PathNotFound`.
  - `relative(scope: SearchScope, absolute: Path) -> str`: a forward-slash path relative to the root
  - `text_files(scope: SearchScope, folder: Path) -> Iterator[Path]`: sorted. It never descends into ignored folders, and skips ignored files, binary files and anything whose resolved path leaves the root.
- Produces (`tests/unit/retrieval/conftest.py`): fixture `repo(tmp_path) -> Path` that builds:

### Task 5: `grep`

**Files:**
- Modify: `backend/app/retrieval/direct/search.py` (add `grep`)
- Create: `backend/tests/unit/retrieval/test_grep.py`

**Interfaces:**
- Consumes: `text_files`, `relative` (Task 2), `symbols` and `enclosing` (Task 4).
- Produces: `DirectSearch.grep(self, pattern: str, path: str = ".") -> str`. Hits are grouped by file in `text_files` order. Each file has the header `"{path} ({n} hits)"`. Each hit is printed as:
  - `"  in {outer} > {inner}"`, only when `enclosing` finds symbols
  - its context lines `"  {n}: {text}"`, and the hit line itself as `"  {n}> {text}"`

  Overlapping context is merged. At most `MAX_GREP_HITS` hits are printed. Past that, it ends with `"... {k} more hits in {f} more files"`. With no hits it returns `"no matches"`. A `CannotOutline` for a file just drops its symbol labels.
