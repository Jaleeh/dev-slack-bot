# Part one: the empty answer

## What the Ollama log already shows (2026-10-27)

The spike's `voucher-guest-rejected` run with thinking on (20:53:30–21:03:11 in `~/.ollama/logs/server.log`) made 8 model calls for 16 tool calls:

| Call | Prompt tokens | Of context | Truncated |
|---|---|---|---|
| 1–7 (with tools) | 851 → 15,818 | 32,768 | no |
| 8 (forced "Answer now", tools off) | 19,324 | 32,768 | no |

- **Context overflow is ruled out for this run.** The final prompt used 59% of the context, and Ollama logged `truncated = 0`.
- The final call generated **86 tokens** and stopped normally. It didn't hit an output limit, and it had over 13,000 tokens of room left. So the model chose to stop after 86 tokens, and none of them reached `content`.
- The spike printed only `reply.content`. Whatever the 86 tokens were (thinking, a tool call, or something else) was thrown away.
- **Side finding for part two:** the tools-off call missed the prompt cache (`sim = 3/19324`) and re-read all 19,324 tokens. That took 4 min 10 s of the 4 min 20 s. Removing the tools changes the start of the prompt, so the forced final answer costs a full re-read.

## Suspects left

| Suspect | Sign in the captured reply |
|---|---|
| A. It tried another tool call | `tool_calls` not empty, or tool-call text in `content` or in the thinking |
| B. It only thought | `reasoning_content` holds the 86 tokens, `content` empty, `done_reason == "stop"` |
| C. The forced message confused it | The same as B, but a different final message gives an answer |

## Global Constraints

- The probe lives in `.superpowers/sdd/2026-10-27-step-3.2-agent/` (git-ignored). Nothing in part one goes in `backend/`.
- It reproduces the spike exactly: the same `spike_agent.py` tools, prompt, `temperature=0`, `num_ctx=32768`, thinking on and the 15-call limit. Ollama samples greedily at temperature 0 (the log shows `temp = 0.000 … greedy`), so the same prompt should give the same reply.
- The maintainer runs every model command. Each one takes minutes.
- Only this plan file is committed in part one.

## Review Focus

1. **The rerun doesn't reproduce the empty answer** (for example, a different Ollama version changed the output). Then the probe still saves the history at the limit, and Task 2 replays that. If no run comes back empty, the cause is recorded as "not reproduced", and part two keeps the spec's fallback answer as the only guard.
2. **The reply has `tool_calls` even though no tools were bound.** The probe must print `tool_calls` rather than assume they're empty. Task 1, step 2.
3. **Replays come back different on the same prompt.** Each variant runs 3 times, so a flip shows up as a difference between runs, not as a cause.

## Part one result (2026-10-27)

**Cause: suspect A. With the tools removed, the model still wrote a tool call.** Ollama parsed it into `tool_calls`, so `content` was empty. The spike read only `content` and took the tool call to be the answer.

The forced reply, the same in all 3 runs: 86 tokens, `done_reason = stop`, 107 characters of thinking, and `read_file(path="src/oscar/apps/basket/views.py", start_line="399", end_line="568")`. Its line numbers came back as strings, because no tool definition was there to type them. The rerun gave the spike's same 16 tool calls and 19,324-token final prompt. `repro.txt` stops after the history was saved, so the final reply comes from the `as-is` replay.

| Variant | Answered (of 3) | Output tokens | Final call time, first / repeat |
|---|---|---|---|
| `as-is` | 0 (tool call each time) | 86 | 12 s (cached) |
| `think-off` | 3 | 184 | 26 s / 26 s |
| `tools-on` | 3, no tool calls | 566 | 2 min 10 s / 1 min 20 s |
| `system-note` | 3 | 656 | 1 min 40 s / 1 min 30 s |

Every replay gave the same reply on all 3 runs (greedy sampling). All three working variants give the setup-issue verdict and the "once per customer, guest not signed in" cause.

**Fix chosen for part two:**
1. At either limit, **keep the tools bound** and add the "answer now" message. Run no tool call from that reply. This differs from the spec's "tools are removed". The model only wrote a tool call when the tool definitions were missing. Keeping them also keeps the prompt's start the same, so Ollama's prompt cache can be reused. In the spike, removing the tools forced a full re-read of a 19,324-token prompt. The replay's first `tools-on` call was cold (2 min 10 s) because the loop's cache wasn't there. Part two's timings confirm the saving.
2. **Only `content` counts as an answer.** Tool calls in the forced reply are never run. If its `content` is empty (for example, it is only a tool call), the asker gets "I couldn't work this out from the code", as the spec says.

**Rejected:**
- `think-off`: it answers and is the fastest. But it still removes the tools, which is the condition behind the stray tool call. Kept as the fallback if `tools-on` fails on other questions in 3.3.
- `system-note`: it answers. But it also removes the tools, and the system message in the middle of the conversation is unusual for chat templates.
- A larger context, shorter tool output, or trimming old output: the prompt was at 59% of the context and wasn't truncated.

**Carried into part two:**
- `AGENT_CONTEXT_TOKENS` stays at `32768`, and the read cap stays at 200 lines. The re-read rule is unchanged, since nothing is trimmed.
- Record `prompt_eval_count`, `eval_count` and `done_reason` per model call in the result. That makes a future overflow visible.
- Evidence is one question, so the fallback stays as the guard.

# Part two: the agent

**Architecture:** A new `app/agent/` package. `guardrails.py` is the pure core: a frozen `Progress` value and the decisions on it (repeat, re-read, search first, limits, where to go next). `graph.py` is a hand-written LangGraph `StateGraph` with nodes `search → tools → search …`, then `finish → rewrite`. It holds only I/O: model calls, tool runs, timing. `prompts.py` holds the wording, and `tools.py` wraps `DirectSearch` as LangChain tools. Settings live in `app/config/agent.py`, need no database, and `EvalSettings` extends them. `make ask` lives in `evals/ask.py`.

**Tech Stack:** adds `langgraph` 1.2, `langchain` 1.4 and `langchain-ollama` 1.1 (moved to main dependencies), and `regex` (grep time limit).

## Library check (spec: "check the agent helpers in LangChain 1.x and LangGraph")

- `create_agent` with `ToolCallLimitMiddleware` was checked (2026-10-27). Its exit behaviours are `continue`, which blocks calls over the limit and lets the model keep going with no "answer once, then stop", `end`, which stops with a canned message and no answer, and `error`. None of them gives "one forced answer with the tools still bound". The repeat, re-read and search-first rules would all need a custom middleware anyway.
- **Chosen: a hand-written `StateGraph`** with the decisions in pure functions. It's still LangGraph, so step 5's Postgres checkpointer fits. *Builder's call.*
- LangGraph's default `recursion_limit` is 25 steps, and a 15-call run takes more. `ask` passes `recursion_limit = 4 * max_tool_calls + RECURSION_MARGIN` (`RECURSION_MARGIN = 10`).
- LangChain's fake chat models don't implement `bind_tools`. The tests use a `GenericFakeChatModel` subclass whose `bind_tools` returns itself.

## Global Constraints (part two)

- Branch `step-3.2-agent`, a normal PR off `main` (no stacks).
- `app/agent/` and `app/config/` import nothing from `evals/`. `evals/` may import `app/`.
- Settings and defaults, as the spec gives them: `CHAT_MODEL=ollama:ornith:9b`, `AGENT_THINKING=true`, `AGENT_MAX_TOOL_CALLS=15`, `AGENT_MAX_TOKENS=1000000`, `AGENT_CONTEXT_TOKENS=32768`, `RETRIEVAL=direct` (the only value), `SEARCH_SKIP` (a JSON list, defaulting to `DEFAULT_SKIP`).
- Search model: `temperature=0`, `reasoning=AGENT_THINKING`, `num_ctx=AGENT_CONTEXT_TOKENS`, four tools bound **on every call, including the forced one** (part one). Rewrite model: same model, `reasoning=False`, no tools. The Ollama-only keyword arguments are passed only for `ollama:` models, as `build_judge` does.
- Fixed wording (`prompts.py`):
  - `SEARCH_FIRST = "Search the code before answering."` (spec)
  - `ANSWER_NOW = "Tool limit reached. Answer now with what you have."` This is the replayed text, used for every limit.
  - `FALLBACK = "I couldn't work this out from the code."` (spec)
  - `REPEAT_BLOCKED = "You already made this exact call; its result is above. Try something else, or answer."`
  - `REREAD_BLOCKED = "You already read these lines; they are above. Read other lines, or answer."`
- Tool errors: a `SearchError` becomes the tool's reply text. So does a pydantic `ValidationError` from bad model arguments, and an unknown tool name. Any other exception propagates as a bug. *Our call: bad arguments are the model's mistake, not ours.*
- Every tool call counts toward `AGENT_MAX_TOOL_CALLS`, blocked ones included. All calls in one reply run before the limit is checked. That's the spike's behaviour, and it lets a run go a few calls past the limit.
- Tokens are `input_tokens + output_tokens` from each reply's `usage_metadata`, summed over the question, rewrite included. Only the search loop checks the limit.
- **Commit only when the user says so.**

## Review Focus (part two)

1. **The forced reply is only a tool call (the spike's bug).** The asker gets `FALLBACK`, `is_empty` is true, and the tool call is not run. Tested in Task 8.
2. **The model sends `start_line="399"` as a string, or leaves out a required argument.** Strings are coerced by the tool schema. A missing argument comes back to the model as text, with no crash. Tested in Task 8.
3. **A catastrophic regex (`(a+)+$`) on a long line.** grep returns `BadPattern` "too slow" within about a second and doesn't hang. Tested in Task 5.
4. **`RETRIEVAL=vector` or a malformed `SEARCH_SKIP`.** `make ask` stops with a one-line message naming the setting, with no traceback. Tested in Tasks 6 and 9.
5. **The rewrite comes back empty.** The asker gets the draft, not the fallback, because the draft is a real answer. *Our call.* Tested in Task 8.

- Graph: `search` (invoke the bound model, add tokens, record a `ModelCall`) → `after_reply` → `tools` | `nudge` | `finish`. `tools` runs each call through `check`. It replies with the blocked text or the tool output, calls `on_call`, then `after_call`. It then checks `stop_reason`, and on a stop it appends `ANSWER_NOW`. It always returns to `search`. `nudge` appends `SEARCH_FIRST`, sets `nudged`, and returns to `search`. `finish` sets the draft from the last reply's `content`. Empty `content` gives the answer `FALLBACK`, `is_empty=True`, and the graph ends. Otherwise it goes to `rewrite`, whose `content` is the answer, or the draft if the rewrite is empty.
- `scripted_model.py`: `ScriptedModel(GenericFakeChatModel)`, with `bind_tools` returning `self`. Each test scripts its `AIMessage`s, with `tool_calls` and `usage_metadata`, and runs against a three-file `tmp_path` repo (`src/voucher.py`, `src/basket.py`, `README.md`).
