# Step 3.3: Agent Eval Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `make eval-agent` runs the real agent on every question, or the ones named in `IDS`, and scores retrieval and answers from that one run. Then the maintainer saves a baseline run and a grader hand-check. (A docs-off run was planned too; it's deferred, see Task 4.)

**Architecture:** Scoring is pure and lives in `evals/agent_scores.py`: picking questions, the ranked file list, the grader's evidence, per-question scores and the run metrics. `evals/agent_runner.py` is the shell. It loads settings and the question set, fetches the sample repo, asks the agent, calls the judge and rewrites the results file after each question.

**Tech Stack:** Python 3.14, LangGraph agent from 3.2, the step 2.6 grader, pydantic, `ornith:9b` (agent) and `gemma4:e4b` (judge) on Ollama.

**Spec:** [`docs/specs/2026-10-27-step-3-direct-retrieval.md`](../specs/2026-10-27-step-3-direct-retrieval.md), section "3.3 Agent eval"

## Global Constraints

- Branch `step-3.3-agent-evals`, a normal PR off `main`.
- `app/` imports nothing from `evals/`. `make eval` is unchanged.
- **Ranked list:** the files the agent read or outlined, in first-touched order (`AgentResult.files`, which the agent makes repo-relative through `DirectSearch.repo_path`). Files that only showed up in grep hits don't count.
- **Answers:** the step 2.6 `grade()` on `AgentResult.answer`. The code it's judged against is the text returned by the tool calls that ran (`Outcome.RAN`). Blocked, failed and folder-listing calls are left out.
- **Fallback answers** (`AgentResult.is_empty`) go to no judge. Each one has no checks, scores 0 on facts, sits outside the faithfulness counts and is counted as **empty**.
- **Filter:** `IDS` is a space-separated list of question ids. Unset or blank means all 30. An unknown id stops the run before any model call, naming the id.
- **Results file:** `evals/results/agent-<started_at:TIMESTAMP_FORMAT>.json`, rewritten after every question. There is no resume: rerun the rest with `IDS=`.
- Progress goes to stderr after each question, as in `eval-answers`. Every stop goes through `run_record.stop("eval-agent", ...)`.
- The maintainer runs every model command. Commit only when the user says so.

## Review Focus

1. **The agent reads a file as `/…/django-oscar@4.2.1/src/x.py` or `./src/x.py`.** Absolute paths inside the root pass the tools, and `Call.path` keeps them absolute. The ranked list must still match `src/x.py`, or recall drops for no reason. Tested in Task 1.
2. **Ollama dies at question 17 of 30.** The file keeps the first 16 questions, and the stop message names the file and says to rerun the rest with `IDS=`. Tested in Task 2.
3. **A typo in `IDS`.** The run stops before any model call and names the bad id, so it doesn't waste a multi-hour run on the wrong set. Tested in Tasks 1 and 2.
4. **The judge's prompt is silently cut short by Ollama.** All the tool output for one question can be tens of thousands of characters, and the judge runs at Ollama's default context. Then the faithfulness verdicts mean nothing. Each question records `evidence_chars`, and Task 4 checks the Ollama log for truncation.
5. **The judge sees the fallback text.** "I couldn't work this out from the code" claims nothing, so it would pass faithfulness and inflate the count. Fallbacks are never graded. Tested in Task 1.

### Task 1: Pure scoring

**Files:**
- Create: `backend/evals/agent_scores.py`
- Test: `backend/tests/unit/evals/test_agent_scores.py`

**Interfaces:**
- Consumes: `AgentResult`, `ToolCallRecord` (`app.agent.graph`), `Outcome`, `StopReason` (`app.agent.guardrails`), `CheckResult`, `fact_score` (`evals.grader`), `FAITHFULNESS` (`evals.answer_set`), `Question`, `QuestionSet`, `recall_at_k`, `reciprocal_rank`.
- Produces:
  - `class UnknownQuestions(ValueError)`, whose message names every unknown id.
  - `select_questions(question_set: QuestionSet, ids: Sequence[str]) -> tuple[Question, ...]`. Dataset order. Empty `ids` gives every question.
  - `evidence(result: AgentResult) -> str`. For each `RAN` record, a `# {record.signature}` line, then its output. Blocks are joined with a blank line.
  - `@dataclass(frozen=True) class Attempt`: `result: AgentResult`, `checks: tuple[CheckResult, ...]` (empty for a fallback), `evidence: str`.
  - `class ToolCallEntry(BaseModel)`, frozen: `name: str`, `args: dict[str, object]`, `outcome: str`.
  - `class QuestionScore(BaseModel)`, frozen: `id`, `files`, `recall_at_5`, `recall_at_10`, `reciprocal_rank`, `checks`, `is_empty: bool`, `draft`, `answer`, `tool_calls: tuple[ToolCallEntry, ...]`, `tokens: int`, `seconds: float`, `stop: str`, `evidence_chars: int`, plus computed `fact_score` (0.0 when `is_empty`).
  - `score(question: Question, attempt: Attempt) -> QuestionScore`
  - `class FaithfulnessCounts(BaseModel)`, frozen: `passed`, `failed`, `unclear`, `ungraded`.
  - `class AgentMetrics(BaseModel)`, frozen: `recall_at_5`, `recall_at_10`, `mrr`, `fact_score` (mean over all questions, empties as 0), `all_facts_stated` (count), `faithfulness: FaithfulnessCounts`, `inconclusive` (non-empty answers with any `unclear` or `ungraded` check), `empty`, `seconds_total`, `seconds_mean`, `tokens_total`, `tokens_mean`.
  - `agent_metrics(scores: Sequence[QuestionScore]) -> AgentMetrics`. Callers never pass an empty sequence.

- Produces:
  - `COMMAND = "eval-agent"`, `IDS_ENV = "IDS"`
  - `class AgentRunConfig(BaseModel)`, frozen: `questions_path`, `cache_dir`, `results_dir`, with the same defaults as `RunConfig`.
  - `class RunSetup(BaseModel)`, frozen: `started_at`, `git_commit`, `dataset_version`, `repo`, `ref`, `ids: tuple[str, ...]`, `agent: AgentSettings`, `judge_model: str`.
  - `class AgentRun(BaseModel)`, frozen: `setup: RunSetup`, `questions: tuple[QuestionScore, ...]`, plus computed `metrics: AgentMetrics`.
  - `@dataclass(frozen=True) class Harness`: `agent: Agent`, `judge: BaseChatModel`.
  - `@dataclass(frozen=True) class AgentRunPlan`: `setup: RunSetup`, `questions: tuple[Question, ...]`, `repo: Path`, `path: Path`.
  - `evaluate_agent(plan: AgentRunPlan, harness: Harness) -> AgentRun`. For each question it calls `ask`, then `grade` unless the answer is empty, then `score`. It logs one stderr line (`[3/30] id: recall@5 1.00, facts 2/3, faithfulness pass, 9 calls, 410 s`, or `… empty …`), writes `AgentRun(setup, done so far)` to `plan.path`, and returns the final run. Model errors propagate.
  - `main(ids: Sequence[str], config: AgentRunConfig = DEFAULT_CONFIG) -> int`
  - Makefile: `eval-agent: ## Run the agent on every question, or IDS="a b" (needs Ollama; a full run takes hours)`, with recipe `cd backend && uv run python -m evals.agent_runner`, plus `export IDS`, and `eval-agent` in `.PHONY`. Run as a module, it reads `os.environ.get("IDS", "").split()`.

Flow in `main`:
1. `AgentSettings()` and `EvalSettings()`. A `ValidationError` or `SettingsError` stops with `bad setting: …`.
2. `build_judge`. A `ValueError` or `ImportError` stops, as in `eval-answers`.
3. Load the question set and `select_questions`, then fetch the repo and read `git_commit()`. `InvalidDataset`, `yaml.YAMLError`, `UnknownQuestions`, `SampleRepoError` or `RepoCommitError` stops. No model call happens before this point.
4. `evaluate_agent`. `httpx.TransportError` and `ollama.ResponseError` stop with the `ask` wording, plus `; finished questions are in <path>, rerun the rest with IDS=` when the file exists.
5. Print the summary: the metrics as `format_rows`, then the results path.

## Baseline result

Run `agent-20261028T135238Z`: `ornith:9b` with thinking on, judge `gemma4:e4b`, 30 questions, default search scope.

The agent is deterministic: `agent-20261029T083527Z` gave the same 30 answers and token counts. So the judge scores are the mean (lowest–highest) over 3 gradings of the same answers: the two runs plus one `make regrade` pass (`regrade-20261029T125804Z`). Retrieval, time and tokens don't depend on the judge.

## Grader hand-check

Done 2026-10-30 on 10 baseline answers (48 checks): 5 where the judge's verdicts differed between the 3 gradings, 3 with low scores and 2 with perfect scores. Claude did a first pass of every check against the answer and the Oscar source, and the maintainer reviewed every disagreement with the judge. "Grader" is the 3 gradings, in order.

The judge's majority verdict was right on 43 of 48 checks. All 5 misses are passes that should be fails, and the judge gave the same pass all 3 times, so this is a bias, not noise. Three of them are faithfulness checks, so the baseline's faithful pass count (26.0) is too high. ADR-004 is reopened.
